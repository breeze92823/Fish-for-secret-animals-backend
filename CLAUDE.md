# Fish for Secret Animals — BACKEND (game server)

Frontend (3D client) lives at `../Fish-for-secret-animals` (its CLAUDE.md describes the game; the message contract below is mirrored in its `src/net.js`, `src/game/state.js` and `src/config.js`). Colyseus + Mongo, ported from the Kayak-and-surf server.

**Messages.** Client -> server: `saveGame` (the whole save), `identify`, `adReward`, `claimDaily` / `dailyRefresh`, `spin`, and the presence messages `pose` / `pen` / `throw` / `emote` / `setAvatar`. Server -> client: `welcome`, `game`, `serverError`, `spins`, `spinResult`, `daily`, `dailyResult`, `adResult`, `boss`, `bossWin`, `leaderboard`, `invites`, `throwFx`, `emoteFx`. The server holds no gameplay rules (client-authoritative); it bounds what it stores and relays.

**Keeping the two repos in step** (a contract change goes in both): `BASE_COUNT` = client `PENS.xs.length`; `PEN_MAX` = `ECONOMY.maxCapacity`; `DAILY_DAYS` = `DAILY.days.length`; `SPIN_*` / `SPIN_WEDGES` = `SPIN`; `BOSS_*` = `EVENTS.boss`; `LEADERBOARDS` = config `LEADERBOARDS`; `GAME_SLUG` = config `GAME_SLUG`; every key of the client's `S` (`fresh()` in state.js) must be in `GameSave` / `sanitizeGame`, with bounds in `GAME_LIMITS` that cover the client's own caps (e.g. `luckyCredits` 99, `lures` 999, sizes 0..9 vs 5 `SIZES`, variants 0..9 vs 4 `VARIANTS`, `benchTier` vs `TRAINING.benches`). All catalog ids (rods, baits, trails, animals, potions, season girls) must match `ID_PATTERN` (<= 32 chars of `A-Za-z0-9_-`) or the server silently drops them.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- **Bases** (`src/bases.ts`, `test/Bases.test.ts`): the hub has `BASE_COUNT` (5) fenced pens and the room is exactly that big (`ROOM_MAX_CLIENTS = BASE_COUNT`, keep both in step with the client's `PENS.xs.length`), so every player gets a base of their own. `onJoin` assigns `PlayerState.base` = the lowest free index (`pickBase`), or the join option `base` when a rejoining player asks for theirs back and it is free; the newcomer also gets a `welcome` { base, bases } message. A base is freed when the session is forgotten (`forgetSession`: consented leave, reconnection window over, same-account eviction). The deploy workflow sends `roomSize` = `BASE_COUNT` (= 5) to Bloxity (docs.bloxity.io, Multiplayer matchmaker: send `roomSize`, never `seatCap`; Boxity chooses the pod capacity itself, in whole rooms).
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp, base? })`). Client-authoritative: the server only bounds and shapes saves (`src/game.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- The client keeps NO progress in the browser: this server's Mongo doc (its `game` field) is the player's only save. A guest's (or a serverless session's) progress lasts the page only.
- Sessions: `identify` (`{ token, userId, username, pfp, ref }` after a sign-in/out mid-session) re-resolves the account and answers with that account's `game`. `serverError` (the save could not be read: saving stays off so it is never overwritten). Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted. Roster (`PlayerState`): `username`, `signedIn`, `pfp` (Bloxity profile picture URL, http(s) only, max `PFP_MAX_LEN`, "" = none), `base`, plus the presence fields below (`test/Roster.test.ts`).
- Document shape (`PlayerDoc` in `db.ts`): `game` (the save, see below), `bestOdds` / `catches` / `income` (copied out of the save, indexed), `username`, `lastSeen` (stamped when a session ends), `invites` / `invitedBy`, the server-owned `spins` / `spinAt` and `dailyDay` / `dailyLast` / `dailyClaimed`, `version`, `updatedAt`. Documents written by earlier versions of the server may carry other fields; nothing reads them.
- Spin wheel (`src/spin.ts`, constants `SPIN_*`): server-authoritative, unlike the rest of the save. Each session's `{ spins, nextAt }` lives in `spinStates` (read from the doc's `spins`/`spinAt` on load; a new player gets `SPIN_START`), one free spin accrues every `SPIN_EVERY_MS` of real time up to `SPIN_CAP` (the clock waits while capped). After the load the server sends `spins` { spins, nextAt, serverTime }; `spin` spends one, rolls a `SPIN_WEDGES` id by weight and answers `spinResult` { ok, id, spins, nextAt, serverTime } (or { ok: false, reason: "loading" | "none" }), then writes `spins`/`spinAt` itself. `saveGame` never carries them (`sanitizeGame` builds only the game save). Guests / no-DB sessions keep theirs in memory for the connection. The client grants the prize (its `SPIN.wedges` by id).
- Daily Reward (`src/daily.ts`, `DAILY_DAYS` = the client's `DAILY.days.length`): server-authoritative on the server's UTC clock. Doc fields `dailyDay` (days unlocked this cycle), `dailyLast` (UTC day index of the last unlock), `dailyClaimed[]` (0-based days), written only by the server (`saveDaily`), never by `saveGame`. On load (`loadProgress`) the state goes into `dailies` per session, today unlocks (`rollDaily`: +1 day per new UTC day, capped; all claimed -> back to day 1) and the client gets `daily` { unlocked, claimed, nextAt, serverTime }. `claimDaily` { day } answers `dailyResult` { ok, day, reason?: "loading" | "locked" | "save", ...view } (ok only once stored); `dailyRefresh` re-rolls after midnight and answers `daily`. Guests / no-DB sessions keep theirs in memory for the connection. Tests: `test/Daily.test.ts` (shared fake Mongo in `test/fakePlayers.ts`).
- Leaderboards (`src/leaderboard.ts`, `test/Leaderboard.test.ts`): the plaza's three boards. Top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`bestOdds` = best pull, `catches` = animals caught, `income` = money per second), read with find/sort/limit into one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; each player's own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). Server -> client `leaderboard` { boards: { stat: [{ name, value }] }, ranks: { stat: n | null } }, sent after each load and to everyone every `LEADERBOARD_EVERY_MS` (room clock). `connectDb` creates a descending index per stat. The test fake supports just that find/countDocuments shape.
- Presence (`src/presence.ts`, `test/Presence.test.ts`, `test/Hub.test.ts`): what the others draw in the hub, relayed through the roster as sent, only bounded. Roster fields `x`/`y`/`z` (feet), `yaw` (wrapped to -PI..PI), `speed` (m/s), `avatar` (Bloxity look JSON, at most `AVATAR_MAX_LEN`, never parsed). Messages `pose` { x, y, z, yaw, speed, ... } (~10/s, bounds `POSE_BOUNDS`) and `setAvatar` { avatar }; the join options may carry `pose` and `avatar` too.
- `src/constants.ts` bounds must cover the client's `src/config.js` (catalog ids match `ID_PATTERN`; money up to `CURRENCY_MAX` = 1e33, the dearest rod is ~3e15). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `BASE_COUNT` read from `src/constants.ts` (= the room's `maxClients`, see Bases above). Needs repo var/secret `LEGION_GAME_ID` (= `fish-for-secret-animals`, the client's `GAME_SLUG`) and secret `LEGION_DEPLOY_TOKEN`.

## Hub presence (Fish for Secret Animals)
`PlayerState` also carries what the others draw (presence.ts, `test/Hub.test.ts`): `uid` (Bloxity id, "" = guest, for chat bubbles), `grounded`, `vy`, `arm` + `armOn`, `lean`, `act` ("" | aim | train), `food`, `carry` ("baddieId:size"), `income`, `pen` ("id:size,..." capped at `PEN_MAX` = the client's ECONOMY.maxCapacity). Messages: `pose` (extended), `pen` { list }, `throw` { food, from, to, dur, peak, power, lucky } and `emote` { id } (relayed to everyone else as `throwFx` / `emoteFx` with the sender's `sid`, bounded by `cleanThrow` / `cleanEmote`), `setAvatar`.

## Game save and rewarded ads (Fish for Secret Animals)
- `src/game.ts` `sanitizeGame`: the client's whole progress (`S`) bounded and shaped; stored as the `game` field of `players` by the `saveGame` message (ignored for guests, without a database, and before the session's load answered). The join answer is a `game` message { game | null, serverTime } (`serverError` when the read failed: the client then keeps saving off). `test/GameSave.test.ts`. The client keeps nothing in the browser.
- `src/ads.ts`: `adReward` { placement, rewardToken, apiUrl } -> verifies the token with Bloxity (`POST {api}/v1/ads/reward/verify` { gameSlug, rewardToken }; the api is `BLOXITY_API_URL` if set, else the client's apiUrl only when it is an https bloxity.io host, else prod; slug = `GAME_SLUG` / `BLOXITY_GAME_ID`) and answers `adResult` { ok, placement, reason? }. The client grants the reward only on ok.

## Bloxity: identity, Open Rooms and leaderboards
- `src/auth.ts`: the client sends its Bloxity `token` in the join options / `identify`; the server verifies it with Bloxity (`POST {api}/v1/auth/game-token/verify`) and only the returned account is ever a user id (name and picture come from Bloxity too). A missing or unverifiable token is a guest (never saved); a client-sent id is believed only outside production (`NODE_ENV` not production, or `ALLOW_CLIENT_IDS=true`). `onJoin` takes the base synchronously before it awaits the verification.
- `src/legion-room-reporter.ts` (same contract as the reporter in the docs.bloxity.io "Show your live rooms" prompt, env names included): every 2 s posts this pod's rooms to the matchmaker (`MATCHMAKER_REPORT_URL`/<gameId>/rooms, bearer `BLOXITY_REPORT_TOKEN`) so the game's Bloxity page lists them (Open Rooms, Join -> `?roomId=`). A no-op unless Bloxity hosting injected those env vars plus `BLOXITY_GAME_ID`. Started from `index.ts` after `listen`.
- Leaderboards: `LEADERBOARDS` in `constants.ts` (ids/settings mirror the client's `config.js`; permanent once declared). `saveGame` copies `bestOdds`, `catches`, `income` out of the save to the document root (indexed, ranked by `leaderboard.ts`, sent to everyone as `leaderboard` { boards, ranks } after the load and every minute: the plaza boards) and, for verified accounts, queues them for `reporter.ts` (batched every 15 s to `/v1/leaderboards/hosted/{gameId}/report`, `legion_<id>`). Tests: `Leaderboard`, `Reporter`, `RoomReporter`.

## Hungry Giant, spin prizes and save extras (Fish for Secret Animals)
- `src/boss.ts` (`test/Boss.test.ts`): the room-wide event at `BOSS_AT_MIN` past every UTC hour for `BOSS_LENGTH_MIN` minutes (client `EVENTS.boss`, keep in step). `WorldRoom.tickBoss` (1 s clock + on join / throw) starts a visit (`need` = `BOSS_NEED_PER_PLAYER` x players then) and broadcasts `boss` { key, on, fill, need, won, endsAt }; each `throw` while she is here feeds her (`feedBoss`) and re-broadcasts `boss`; the filling throw broadcasts `bossWin` { key, throws: { sessionId: n } } (each client pays its own reward).
- `SPIN_WEDGES` ids are the client's `SPIN.wedges` ids (cash1, luck, cash5, lucky, income, jackpot).
- `game.ts` keeps pen / hotbar `v` (variant) and `a` (season girl's area), `tickets`, `lures`, `potions`, `recordPaid`, `indexPaid`, `titles` and the extra `stats` (bestDist, bestStreak, bestVariant, bestRarity, bestArea). Presence `pen` entries carry `:v` when a variant.

## Friend invites
`creditInvite` (WorldRoom): a Bloxity-verified player who is NEW to the game (no document yet) and joined with `ref` (the inviter's account id, from the invite link) gets a document with `invitedBy` (an upsert that only inserts, so an account counts once) and the inviter's `invites` is `$inc`ed (the inviter must already exist and cannot be the invitee; guests never count). The count is sent as `invites` with the `game` message and, when the inviter is in the room, live as an `invites` message. The client turns it into an income boost. `test/Invites.test.ts`.
